# OCR Integration & Troubleshooting Summary

This document summarizes the changes made to the `@cloudpix/worker` service to integrate OCR (Optical Character Recognition) and the challenges resolved along the way.

## 1. Local Development & Docker Permission Conflicts
**Challenge:** 
When attempting to install `tesseract.js` using `pnpm` in the WSL environment, we encountered `ERR_PNPM_UNEXPECTED_STORE` and `EACCES: permission denied` errors.
**Root Cause:** 
The `node_modules` directory was previously generated by a Docker container running as the `root` user. This caused local permission conflicts and a mismatch with the WSL `pnpm` store.
**Solution:** 
- Ran `sudo chown -R $USER:$USER .` to reclaim ownership of the project files from Docker.
- Ran a fresh `pnpm install` locally to re-link the dependencies to the local WSL store.

## 2. TypeScript Build Failure in Worker
**Challenge:** 
The Docker build for `cloudpix-worker` failed with `error TS2366: Function lacks ending return statement` in `ocr.service.ts`.
**Root Cause:** 
The `extractText` function was typed to return a `Promise<string>`, but its `catch` block only logged the error and returned nothing (`undefined`).
**Solution:** 
- Updated the `catch` block to explicitly `return "";`. This satisfies the TypeScript compiler and ensures the application degrades gracefully rather than crashing if OCR fails.

## 3. Tesseract.js Compatibility with WEBP Images
**Challenge:** 
The worker successfully downloaded and compressed `.webp` images, but the OCR extraction silently failed (returning no text and throwing no errors).
**Root Cause:** 
`tesseract.js` relies on standard image decoding natively and does not reliably parse `.webp` image buffers directly.
**Solution:** 
- Imported `sharp` into `ocr.service.ts`.
- Added a pre-processing step to convert incoming buffers into PNG buffers (`await sharp(buffer).png().toBuffer()`) before passing them to Tesseract. 

## 4. OCR Accuracy on Complex Documents (ID Cards)
**Challenge:** 
When testing the pipeline with a driving license, the extracted text was garbled (e.g., `h/ A Dre = 3`).
**Root Cause:** 
Tesseract is optimized for high-contrast, clean documents (like scanned book pages). It struggles heavily with background noise, watermarks, holograms, varied fonts, and low contrast commonly found on ID cards.
**Solution / Next Steps:** 
- Verified that the pipeline works perfectly using a clean screenshot (`testbody.jpg`).
- **Recommendation:** If the application requires accurate parsing of ID cards or complex real-world photos, we should consider replacing Tesseract with a cloud-based AI service like **AWS Textract** or **Google Cloud Vision API**, which are specifically trained for these scenarios. Or, implement heavy image pre-processing (binarization, grayscaling, and contrast adjustments) using `sharp` prior to OCR.

## Code Changes Overview
- **`apps/worker/src/services/ocr.service.ts`**: Added `sharp` conversion and error handling.
- **`apps/worker/src/services/media-processing.service.ts`**: Added `ocrText` to the `ProcessedMedia` interface and awaited `extractText`.
- **`apps/worker/src/handlers/s3-object-created.handler.ts`**: Passed the `ocrText` result to the database via `assetRepository.updateProcessingResult`.
- **`packages/database/src/repositories/asset.repository.ts`**: Updated the repository method to save `ocrText` to the database schema.
